# Admin console

The admin console for the issuer. Operators use it to manage workloads (clients), token audiences, signing keys, the audit log, operators, and passkeys. It is built with React and TanStack Router / Query, and every UI component comes from [Cloudflare Kumo](https://github.com/cloudflare/kumo). The console is available in Japanese and English.

The Admin Worker (`apps/admin-worker`) serves the built files from the same origin as the admin API.

## Run locally

Run these commands from the repository root. The required Node.js and pnpm versions are in the root `package.json`.

```sh
pnpm install --frozen-lockfile
pnpm --filter @workers-workload-identity/admin-ui dev
```

The Vite dev server proxies `/api` to `http://localhost:8788`. Most screens need a configured Admin Worker and an authenticated session. For deployment steps, see the [deployment guide](../../docs/guides/deployment.md).

## Change the screens

`src/main.tsx` owns the shared header, the Kumo Sidebar, and routing between screens. Each screen lives in `src/pages/`. Shared behavior such as confirmation dialogs and notifications lives in `src/components/console.tsx`.

- **Components:** Button, Input, Textarea, Select, Checkbox, Table, Badge, Banner, Dialog, Field, LayerCard, Loader, Toasty, Sidebar, Collapsible, and TimeseriesChart come from Kumo. Icons come from Phosphor.
- **Appearance:** `src/style.css` defines colors and layout. The design follows the Cloudflare dashboard: neutral backgrounds, thin borders, a blue primary action, and small corner radii. The main work area is separate from the right-hand information panel, and list search fields are separate from their tables. Mark the primary action with a Kumo Button that has `data-variant="primary"`.
- **Type and touch targets:** The console ships no proprietary fonts and uses the operating system's default fonts. Main controls are at least 44px tall. On narrow screens the navigation collapses, and tables scroll horizontally inside their own container.
- **Charts:** Only the required Kumo and ECharts modules are loaded, lazily, on the Overview screen. Charts are built from API values only and are paired with a numeric table. When there is no data, the chart shows an empty state.

Kumo styles are generated by the Tailwind CSS v4 Vite plugin. `@source` points at Kumo's distributed files. When a Select's values differ from its labels, pass the labels in `items`. Give every form control a `Field` or an explicit label.

The UI shares only the public DTOs and input validation schemas from `packages/contracts`. Domain packages, database schemas, and secrets never reach the browser. Authentication, CSRF headers, and additional authentication (re-authentication for high-impact operations) are handled in `src/api.ts`.

## Language and wording

Operators switch between Japanese and English from the header or the sign-in screen. The choice is saved in the browser. Without a saved choice, the console uses the browser's preferred languages, and falls back to Japanese if neither language matches. If browser storage is unavailable, switching still works for the current page.

`src/i18n.ts` connects i18next to React. `src/locales/ja.json` and `src/locales/en.json` hold the messages. Message keys are the original Japanese strings; change displayed text by editing the values in each locale file. Keep the keys and interpolation variables identical in both files. `pnpm --filter @workers-workload-identity/admin-ui test` reports missing messages, mismatched variables, and Japanese text left in `en.json`.

New components subscribe to language changes with `useLocale()` and read text with `t()`. Pass the selected locale when formatting dates and numbers. Do not recreate forms or data queries when the language changes. Do not translate API field names, client IDs, audience and subject values, or descriptions and records that operators entered.

Screen names follow the English locale file: **Overview**, **Workloads**, **Audiences**, **Signing keys**, **Audit log**, **Administrators**, and **Registered passkeys**, grouped under **Workload identity federation** and **Access management**. Changing a display name never changes roles, grants, or which credentials are revoked.

Audience settings include the signing algorithm and the relying-party checks that key rotation depends on: that authentication succeeds with the selected algorithm, that old and new public keys can be published together, and the relying party's verified maximum JWKS cache duration.

## Test the UI

```sh
pnpm --filter @workers-workload-identity/admin-ui typecheck
pnpm --filter @workers-workload-identity/admin-ui test
pnpm --filter @workers-workload-identity/admin-ui build
pnpm --filter @workers-workload-identity/admin-ui exec playwright install chromium
pnpm --filter @workers-workload-identity/admin-ui test:ui
```

`test:ui` builds the console, serves the production build with `vite preview`, and replaces the API with mock data. It never uses real data or credentials. The browser tests cover all seven screens in both languages, desktop and mobile layouts, accessibility, edit and confirmation dialogs, form submission, role-based controls, keyboard operation, network errors, language persistence, and navigation under `/admin`. Real passkey registration and sign-in with an authenticator, and sign-in through external services such as Cloudflare Access, need separate verification.

The tests are in `e2e/` and `playwright.config.ts`. Screenshots and traces from failed tests go to `test-results/`. To use an existing Chromium, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to its executable path.
