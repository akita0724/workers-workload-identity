この定義はドキュメントの全ページに適用します。コード上の識別子は表記を変えずに使います。

## 登場する主体

| 用語                       | 意味                                                                                                                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **issuer**                 | 発行 Worker です。既定の Worker 名は `oidc` です。ワークロードアサーションに署名し、discovery メタデータと JWKS を公開します。公開 URL は設定値 `ISSUER_URL` であり、`iss` クレームの値です。 |
| **caller**                 | issuer の `IssuerRpc` エントリポイントへの Service Binding を持ち、ワークロードアサーションを要求する Worker です。                                                                           |
| **relying party**          | ワークロードアサーションを受け取って検証するシステム全般です。外部プロバイダーの token exchange と、JWT を直接検証する独自 API の両方を含みます。                                             |
| **プロバイダー**           | relying party として振る舞う外部のクラウドや API サービスです。AWS、Google Cloud、Claude API、OpenAI API などを指します。                                                                     |
| **管理者**                 | 管理画面からポリシーと鍵を管理する人です。ロールは `viewer`、`operator`、`security-admin` の3種類です。                                                                                       |
| **デプロイ権限を持つ主体** | Worker、Service Binding、その `props` を編集できる人、CI ジョブ、API token です。信頼境界の一部です。[セキュリティモデル](./security.md)を参照してください。                                  |
| **デプロイ担当者**         | ステージングと運用のスクリプト（`pnpm staging:*`、`pnpm ops`）を実行して、リソースの作成、Worker のデプロイ、復旧を行う人です。デプロイ担当者もデプロイ権限を持つ主体に含まれます。           |

## ポリシー

| 用語         | 意味                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **client**   | caller を識別する登録情報です。issuer は Service Binding に固定した `ctx.props.clientId` から選びます。client ID は秘密情報ではありません。 |
| **subject**  | client ごとに固定された `sub` の値です。caller は選べません。                                                                               |
| **audience** | 登録済みの `aud` の値です。audience ごとに署名アルゴリズムとアサーションの有効期間を固定し、relying party での確認結果を記録します。        |
| **grant**    | ある client が、ある audience のアサーションを要求できる許可です。                                                                          |

## アサーションと鍵

| 用語                         | 意味                                                                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ワークロードアサーション** | issuer が caller へ返す短命の署名付き JWT です。各ページでは初出以降「アサーション」と呼びます。「JWT」は形式を、「token」は一般的な bearer token を指します。                             |
| **discovery メタデータ**     | `/.well-known/openid-configuration` で公開する限定的な JSON です。OIDC Discovery の完全なメタデータではありません。                                                                        |
| **JWKS**                     | relying party が署名検証に使う、`/jwks.json` の公開鍵セットです。                                                                                                                          |
| **token exchange**           | ワークロードアサーションを受け取り、一時的な資格情報やアクセストークンを返すプロバイダーのエンドポイントです。                                                                             |
| **鍵の状態**                 | `prepared`（公開済み・署名には未使用）、`active`（そのアルゴリズムで唯一の署名鍵）、`verifying`（発行済みアサーションの検証用に公開を継続）、`removed`（廃止済み。`kid` は再利用しない）。 |
| **Rotation Controller**      | 既定で `oidc-rotation` としてデプロイされる Worker です（ソースは `apps/rotation-worker`）。鍵を生成し、秘密鍵を issuer Worker の secret として保存し、鍵の状態を遷移させます。            |
| **先行公開**                 | 新しい鍵を JWKS に掲載したまま署名には使わず、relying party のキャッシュが取得できるようにする期間です。                                                                                   |

## 識別子に「OIDC」を含む理由

既定の Worker 名 `oidc`、binding 名 `OIDC_ISSUER`、SDK の `createOidcClient` と `OidcClientError` は、relying party が利用する OIDC 形式の discovery メタデータと JWKS に由来します。本プロジェクトは OpenID Provider ではなく、ブラウザーログイン、認可エンドポイント、ID Token フローを持ちません。[ワークロード ID フェデレーションとは](../oidc.mdx)を参照してください。

## リリースに関する用語

**アルファ版**は現在のリリース段階で、`v0.1.0-alpha.0` のようなタグを付けた GitHub の prerelease として公開します。公開する契約は今後も変わる可能性があり、外部プロバイダーとの実機検証は完了しておらず、本番利用を支援するバージョンはまだありません。リリース状況ページのゲートをすべて満たすと**ベータ版**に進みます。検証済みの範囲と未検証の範囲は[リリース状況](./release-status.md)にあります。
